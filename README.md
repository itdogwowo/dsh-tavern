# 🏮 dsh-tavern — 酒館模式（v2.5）

> **接手開發的人先讀 [`docs/plan.md`](docs/plan.md)**——狀態、環境、下一步都在那裡。
> 這一份是給使用者看的。

**一間酒館＝你選的一個資料夾。** 這個插件做三件事：

1. **畫 UI**：側邊欄的「酒館街」區塊 ＋ 中間的設定頁
2. **在資料夾裡建立／讀寫檔案**：人物卡、世界書、對話、插圖、設定
3. **（v2.5 新增）真的跟你聊天**：用角色卡當那個對話的系統提示，世界書按關鍵字觸發

第 3 件是靠一個**只在酒館模式裡跑**的 Agent 面做的——它**不在 `dsh web` 的啟動路徑上**，
所以它壞掉只影響那個對話，不會讓 DSH 開不起來。

沒有正則引擎、沒有 agent 接管。
那些東西在 v1 有，但它們都要在 DSH 啟動時跟核心服務打交道，其中任何一個卡住，
**整個 `dsh web` 就開不起來**（使用者在 macOS 上實際遇到完全卡死），所以 v2 整批拿掉。

**模型參數只有兩個：溫度與最多 token**（v2.6.48 起）。它們**不碰啟動路徑**——
掛的是 `agent/request` 這個**每一次請求**的 hook，所以 v1 那個「啟動時卡住」的問題
不會回來。⚠️ **沒有 `top_p`**，因為 DSH 的介面根本沒有那個欄位（見下面「生成參數」）。

```
側邊欄
├── 工作區（DSH 原生，原封不動）
├── 酒館街（收合）              ← 這個插件加的，跟工作區上下並排
│     [ 🍺 酒館街           ＋ ]  ← 點「酒館街」才展開並第一次讀取；＋ 選資料夾
├── 酒館街（展開後）
│     [ 🍺 酒館街           ＋ ]
│     [ 🏮 預設酒館     ⋯ ＋ ]  ← ⋯ 直接進設定；＋ 去「💬 包廂」（已經在那裡再按＝回那間房）
│     [    💬 初次見面    6分钟 ]
├── 其他插件的區塊
└── 设置
```

## 新增酒館時會建立什麼

按 ＋ 選一個資料夾之後，插件只會**在裡面補上缺少的東西**（已存在的一律不動）：

```
<你選的資料夾>/
├── characters/     人物卡：`.json`（酒館格式）或 `.png`（PNG 卡，提示詞住在圖裡）
│                   ＋ 附一張預設的老闆娘（PNG 卡，見下一節）
├── worldbooks/     世界書：一個 .json 一本
├── chats/          房間：chats/<角色>/<房間id>/{room.json, chat.jsonl, art/, files/}
│                   （files/ 是訊息裡夾帶的附件：圖片／檔案）
│                   ＋ 附一間可以直接聊的預設房（房名 老闆娘-xxxx、開場白已寫好）
├── art/            插圖：一項一個資料夾，可以放很多張
├── originals/      舊版匯入留的原版（新匯入不再寫這一份）
├── tavern.json     這間酒館自己的設定（名稱、備註、建立時間、哪張是主圖）
├── custom.css      裝修的範本（**整份註解掉**，要用就把開頭的 * 拿掉）
└── README.txt      說明這個資料夾是什麼
```

`smoke.mjs` 第 4 項把這件事釘死：**新增＝建立那些東西，而且第二次新增不會重建**。

## 新建酒館會附一位老闆娘、一本世界書、一間房間、一份裝修範本

剛開好的酒館不該是空的——面對「0 人物卡 0 世界書 0 對話」很難下手。所以按 ＋ 選完資料夾，
除了上面的結構，還會多這些東西：

```
characters/老闆娘.png    一位可以直接開始的老闆娘（**PNG 卡**：提示詞、開場白、人設、對話示範
                         全都在圖裡面；而這張圖就是她的立繪）
chats/老闆娘/老闆娘-xxxx/ 一間可以直接聊的房間（開場白已經寫在 chat.jsonl 裡）
worldbooks/酒館.json      一本寫著「這間店／老闆娘／店規」的世界書
worldbooks/輸出格式.json  模型要照著吐的格式說明（每輪都注入，不要刪）
custom.css                裝修的範本（整份註解掉）
```

- **提示詞住在卡片裡。** 預設老闆娘就是 `samples/characters/老闆娘.png` 那一份**逐位元組**
  的複製——所以「卡片是唯一真相」，改卡片不必改程式；出貨檔不在時（例如套件少了
  `samples/`）會退回沒有圖的 `.json`，新增酒館不會失敗。
- **只在新建立時給。** 既有的酒館不會被補（讀取路徑永遠不寫檔）；有同名檔案就跳過，
  你自己改過的老闆娘不會被蓋掉。**房間也只在這一輪真的建了老闆娘時才建**，
  免得在使用者自己的角色旁邊冒出一間莫名其妙的房。
- 寫出來的是一般的卡與世界書，**沒有任何隱藏格式**——想改就改，想刪就刪。
- 世界書的條目用**原生形狀**（`entries` 是以字串化 uid 為 key 的物件），
  跟從別處匯入的世界書是同一種東西。

內容寫在 `lib/defaults.js`（角色／世界書）與 `lib/theme.js`（`custom.css` 範本），
全部都可以直接編輯。

## 人物卡：`characters/` 底下 `.json` 與 `.png` 都是卡

真實世界的酒館卡**大多是一個 `.png`**，卡片資料（提示詞、開場白、對話示範）藏在
PNG 的 tEXt chunk（`ccv3`／`chara`）裡。所以：

```
characters/老闆娘.json    沒有圖的卡（酒館自己編的格式，可 diff）
characters/鯨魚娘.png     **PNG 卡**——提示詞住在圖裡面，而這張圖就是她的立繪
```

- **丟進去就會出現**：把一張 ST 的 PNG 卡放進 `characters/`，卡司、海報牆、
  「＋ 新對話」都看得到它（不必匯入）。
- **讀得到就寫得回去**：在面板上改一張 PNG 卡 → 改的是**同一張 PNG**
  （換掉裡面的卡片區塊，**圖的位元組一個都沒動**）。不會偷偷長出一份 `.json`。
- **卡片本體就是立繪**：沒有另外上傳插圖時，頭像與海報牆用的就是卡片那張圖
  （走 `/api/dsh-tavern/card/<id>`）。它不算「插圖」，所以在插圖管理器裡**沒有刪除鈕**。
- 同名時 **`.json` 優先**（那是酒館自己編的那一份）。

「📥 匯入卡片」接受 `.png` 與 `.json`，而且**不轉檔**：

```
匯入 PNG  → characters/<id>.png    位元組原封不動（卡片就是那張圖，也只有這一份）
匯入 JSON → characters/<id>.json
```

- 讀 `chara`（V2）與 `ccv3`（V3），**`ccv3` 優先**、關鍵字**大小寫不敏感**——與 SillyTavern 一致。
- **撞名自動編號**（`鯨魚娘-2.png`），不覆蓋你已經有的那張卡（照 ST 的規矩）。
- 卡片裡**不認識的欄位一律原樣保留**，有測試逐欄位釘住。
- 寫回時**沿用原本的關鍵字**（V2 卡不會被你存一次就變成 V3）。

> ⚠️ PNG 的每個 chunk 開頭是 4 bytes 的長度宣告，一個惡意檔可以宣告 4GB。
> 我們的剖析器**不相信任何長度欄位**，每一步都先確認剩餘位元組夠不夠。
> `smoke.mjs` 第 16 項用一個宣告 `0xFFFFFFFF` 的 chunk 驗證它會瞬間拒絕。

## 插圖：一組圖，指定一張主圖

一個角色不會只有一張圖——微笑、生氣、各種動作的差分，幾十張跑不掉；世界書、對話室、
酒館店面也各有自己的圖。所以模型是「**一個東西 → 一組圖 → 指定主圖**」：

```
art/characters/<卡 id>/微笑.png       ← 人物卡的插圖
art/worldbooks/<書 id>/封面.png       ← 世界書的插圖
chats/<角色>/<房間id>/art/店內.png    ← 這間房的插圖（**跟著房間走**）
art/tavern/店面.png                   ← 這間酒館自己的店面／背景圖
```

- **圖跟著東西走**：看到路徑就知道圖屬於誰，不再是對不上任何東西的孤島。
- **資料夾就是清單**：直接把圖丟進對應資料夾就會出現，不用改任何設定檔。
  （面板的「加入插圖」只是幫你丟進去而已，兩種方式結果一樣。）
- **主圖存在 `tavern.json`**：`assets: { "character:老闆娘": "微笑.png" }`。
  沒有指定時就是檔名排序的第一張；指定的那張被刪掉也會自動退回第一張，
  不會留下指向空氣的設定。
- 面板上：人物卡清單會顯示主圖的小臉、卡片編輯器裡有縮圖格（點縮圖換主圖、
  右上角 ✕ 刪除、可以整批拖進來）。

上傳走**二進位**（不是 base64 JSON）：一張圖常常好幾 MB，base64 會再多 33%。
宿主半會檢查 magic bytes（**不信副檔名**）、限制單張大小、同名自動編號
（`微笑.png` → `微笑-2.png`，不會蓋掉你原本的圖）。

## 附件：訊息裡夾帶的圖片與檔案

對話頁輸入框左邊那顆 **📎** 可以夾帶東西：

```
chats/<角色>/<房間id>/files/筆記.txt   ← 附件（**跟著房間走**）
chats/<角色>/<房間id>/files/照片.png
```

- **圖片**直接給模型看（DSH 的圖片附件），**其他檔案**先上傳再送（DSH 的檔案附件），
  兩條路都是 DSH 自己的機制，酒館只是接上去。
- **同一份位元組也存一份在房間裡**：那才是「這個資料夾帶走就好」的那一份。
  訊息用 `extra.media` 指向它（SillyTavern 的欄位），所以**重新整理之後還畫得出來**。
- 附件資料夾跟 `art/`（插圖）**分開**：插圖是「這個東西長什麼樣」（海報牆、主圖都在讀它），
  附件是「這一則訊息夾帶了什麼」。混在一起會讓主圖挑到一個 PDF。
- 讀取路由跟插圖同一組圍籬（只接受本機同源的請求），而且**非圖片一律當下載**
  （`content-disposition: attachment` ＋ `nosniff`），不讓丟進來的 HTML／SVG 被當文件執行。
- 孤兒附件**不會自動清理**（跟插圖同一個哲學：移除就是移除，使用者按了才刪）。

## 中間的視窗

| 面板（`main` key） | 什麼時候出現 | 內容 |
|---|---|---|
| `tavern` | 側邊欄的 ⋯ | 這間酒館的設定頁：🏠 這間酒館（店面圖／名稱／圖示／備註／移除／資料夾結構）、🎭 人物卡、📖 世界書、💬 對話紀錄 |
| `tavern-chats` | 點一份對話 | 那份對話的檔案資訊與它的插圖（v2 不在這裡跑對話） |

- **人物卡**：表單編輯 8 個常用欄位，其餘欄位原樣保留；檔案一律寫成 SillyTavern 信封。
- **世界書**：原始 JSON 編輯器（世界書格式太多種，不做欄位表單才不會吃掉你的欄位）。
- **移除**只把酒館從清單拿掉，**絕不刪除任何檔案**（插圖也一樣）。

## 舊版留下來的酒館會標成「舊版殘留」

v1 會自動建立／認養一間「預設酒館」。那筆紀錄到了 v2 還留在 `~/.dsh/taverns.json` 裡，
而酒館街預設是收合的——所以使用者**第一次按 ＋**（新增成功後清單會自動展開）才會第一次
看到它，看起來就像「按了新增卻跑出兩間酒館」。

判準是 `tavern.json` 在不在：v2 的 `ensure()` 只要碰過那個資料夾就一定會補上它，
所以**沒有 `tavern.json` ＝ 那個資料夾不是這一版建立的**。面板會把它標成
「舊版殘留」並在設定頁說明清楚，按「移除」只會拿掉那筆紀錄，資料夾與檔案都不動。

## 啟動時什麼都不做（按了才做）

這條是刻意的設計約束，也是這個插件唯一「反直覺」的地方：

| 時機 | 插件做什麼 |
|---|---|
| `dsh web` 啟動、插件掛載、`apply()` | **零請求、零檔案讀取**（`smoke.mjs` 與 `test-client.mjs` 都釘住） |
| 側邊欄畫出「酒館街」標題列 | **零請求**——這區塊一直掛在側邊欄上，所以掛載＝DSH 一開啟 |
| 你按下「酒館街」（展開） | 才第一次送出 `tavern.list` |
| 你按 ＋ 選資料夾 | 才建立 `characters/`… 那些檔案 |
| 你點一間酒館、按 ⋯、點一份對話 | 才讀那個東西 |

為什麼要這樣：v1 就是「一開啟就自己動起來」，結果在 macOS 上整個 DSH 卡死，
而且**看不出來是哪一件事卡住**。現在每一個動作都對應到你按下去的那一顆按鈕，
壞掉時一眼知道該回報哪個按鈕。

## 側邊欄的外觀

度量與互動照抄原生工作區瀏覽器（`ui-workspace` 的 `Rows.module.css` 與區塊標題）：
區塊標題 36px＋28px 圓形按鈕、酒館列 34px、對話列 32px、hover 才出現的 ⋯ 與 ＋、
「展開其餘 N 個」。酒館街與工作區之間有**可拖曳的分隔線**（雙擊回復預設），
拖過一次高度就固定成 px，展開時不會推動上面的工作區清單。

**對話列的行為也照原生會話列**（`sessionRow`）：

| 原生 | 酒館 |
|---|---|
| `slot → title → time → rowActions` 四個部分 | 一樣四個（`dsh-tv-slot` / `-title` / `-time` / `-actions`） |
| 32px、`padding:0 8px`、`border-radius:8px`、`gap:0` | 一樣 |
| hover 與選中同一種底色（`interactive-bg-hover`） | 一樣 |
| hover 時**時間讓位給 ⋯** | 一樣（純 CSS） |
| ⋯ 開「改名／分支／封存」 | ⋯ 開「**改名／分支／刪除**」（封存沒有對應的酒館概念） |
| 改名是**行內輸入框**（`.renameInput`） | 一樣（`.dsh-tv-rename`） |
| 選單是 `createPortal` 到 `document.body`（不會被側邊欄裁掉） | 一樣的做法：自己建一個 body 底下的容器 + 固定座標（客戶端 bundle 只拿得到 `react`，沒有 `react-dom`） |

「分支」是**接 DSH 自己的** `remote.session.fork`（原生那一顆就是它），流程是
`fork` → 開一份新檔 → 把目前看到的訊息寫過去 → `session.bind` 綁到新 session。
沒有綁定（還沒真的聊過）或這台 DSH 沒有 `fork` 時，選單上會直說原因，不給一顆
按了沒反應的按鈕。

圖示：區塊是啤酒杯、每間酒館是彩色燈籠（可換成 12 種預設或任何 emoji）。
⋯ 選單那三顆圖示（筆／分支／垃圾桶）是自己畫的——原生那三顆住在
`@deepseek-ai/dsh-client-ui-primitives`，而客戶端 bundle 的 `require` 只有 `react`。

## 裝修（每間酒館自己的外觀）

介面的每一個顏色、圓角、陰影、字體都走**設計 token**（`--dsh-tv-*`），
所以外觀可以整組換掉，不必改程式。**兩層，從簡單到進階**：

```
<酒館資料夾>/theme.json   ← 顏色、圓角、陰影、字體、對話框樣式（這一節）
<酒館資料夾>/custom.css   ← 上面改不到的形狀與材質（下一節）
```

> **新建酒館時會附一份 `custom.css` 範本**（整份註解掉，所以附了不會改變外觀）——
> 它裡面列了常用類別與幾個例子，要用就把開頭的 `*` 拿掉。
> 既有的酒館不會被補檔案；自己建一個同名檔案也可以。

> ⚠️ **改完要重新載入頁面（F5）。** 同一間酒館不會自動重讀——主題只在
> 「酒館清單被讀到」的時候套一次（展開酒館街、或點進面板就會讀；換到別間再換回來也會重讀）。

### `theme.json`

```json
{
  "base": "dark",
  "style": { "bubble": "paper" },
  "tokens": {
    "surface-0": "#0B0D12",
    "accent": "#7FA8C9",
    "radius-md": "14px"
  }
}
```

- `base` 是 `dark` 或 `light`，沒寫的 token 就繼承基底。
- **不認得的 token（包含打錯的名字）會被忽略**，而且會列在 `dropped` 裡回報——
  不會弄壞主題，但那一行也不會生效。
- 內建色票是「**墨水與暖光**」：深墨底、燈籠暖光當強調色。
- 完整的 31 個 token 與預設值在 `lib/theme.js`（`THEME_TOKENS`）。

**最常改的幾個**：

| 想改什麼 | token |
|---|---|
| 主面板背景 | `surface-0` |
| 卡片／訊息列 | `surface-1` |
| **對話氣泡底** | `surface-2` |
| 邊框 | `line` / `line-soft` |
| 文字三階 | `text-1` / `text-2` / `text-3` |
| 強調色（唯一） | `accent` / `accent-hover` / `accent-soft` |
| **氣泡圓角** | `radius-sm` / `radius-md` / `radius-lg` / `radius-pill` |
| 陰影 | `shadow-1` / `shadow-2` |
| 動效時長 | `speed-fast` / `speed-slow` / `ease` |
| 字體 | `font` / `font-reading` / `font-mono` |

### `style.bubble`（對話框樣式）

顏色之外，氣泡的**形狀**是另一層——token 只能換數值，換不動形狀：

| 值 | 長什麼樣 |
|---|---|
| `bubble` | 預設。圓角氣泡，兩邊分左右 |
| `plain` | 沒有氣泡：只有名牌與正文，像小說排版（長篇閱讀最舒服） |
| `tail` | 氣泡帶一個指向發話者的尾巴 |
| `paper` | 紙張感：漸層底、細邊框、內縮陰影 |

### `custom.css`（進階）

token 與 `style.bubble` 都改不到的（背景圖、材質、動畫、某個元件的細節），
寫在 `<酒館資料夾>/custom.css`。

它的內容會被**包在 `@scope (.dsh-tv-view)` 裡**才注入，所以它碰不到 DSH 自己的
介面（SillyTavern 的 `* { text-shadow }` 污染整個宿主是前例）。也因為如此，
選擇器直接寫 `.dsh-tv-xxx` 就好，**不要再加** `.dsh-tv-view` 前綴：

```css
/* custom.css */
.dsh-tv-bubble { border: 0; border-radius: 14px }
.dsh-tv-bubbleText { font-size: 17px }
```

⚠️ 不支援 `@scope` 的瀏覽器會**整段忽略**——那是刻意的降級（自訂樣式沒生效，
但不會壞掉），不是相容性破口。

> 改版前這個介面有 129 處寫死的顏色、7 種不一致的圓角——那時候換不了主題，
> 因為每個元件都自己挑色。現在元件只准用 token，測試會掃。

## 你是誰：`{{user}}` 與 persona

三格都在**⚙️ 設定**（存在這間酒館的 `tavern.json`，所以整個資料夾帶走時跟著走）：

| 欄位 | 做什麼 | 存在哪 |
|---|---|---|
| **你的名字** | 角色卡裡的 `{{user}}` 換成它。留空＝「你」 | `userName` |
| **你是誰（persona）** | 一段「你是誰」的說明，**接在角色卡後面**一起送進去 | `userPersona` |
| **這間店的規則** | 每輪都要帶進去的規矩（例：店裡沒有現代科技） | `tavernPrompt` |

三格留空時，提示詞與以前**一字不差**——「按預設來就好」。

差別在**備註**那一格：`note` 只給人看，**不會**進提示詞。

> ⚠️ persona 與店規裡的 `{{char}}`／`{{user}}` **也會被換掉**（跟卡片同一條規矩）。
> 不認識的巨集（`{{random}}` 那類）原樣留著，讓你看得見自己的卡用了什麼。

## 生成參數：溫度與最多 token

也在**⚙️ 設定**（整間酒館）與對話頁的 **⚙️ 房間**（只有這一間房）：

- **留空＝不指定**，DSH 與提供方自己決定。兩層都留空時，這一版的行為與以前**完全一樣**。
- **房間蓋過酒館**，而且是**逐欄位**：只填溫度就只蓋溫度。
- 房間那一格按「清除」＝**聽酒館的**（不是把酒館的清掉）。
- ⚠️ **打錯的值不會存**，而且畫面會說「這幾個值沒有存下來」——範圍是
  溫度 `0`～`2`、最多 token `1`～`200000`。**不會**偷偷把它夾到邊界：
  把 `5` 靜靜變成 `2` 會讓你以為自己設成功了。

> ⚠️ **沒有 `top_p`。** 這不是漏掉，而且也不是「DSH 還沒做」——是**它刻意拿掉的**。
> DSH 的 `LlmCallConfig`（`dsh-llm/lib/types/call-config.d.ts`）只有
> `provider`／`model`／`reasoningEffort`／`temperature`／`maxTokens`／`stop`，
> 而它的 README 把這件事寫在「已知限制」那一節（`dsh-llm/README.md:154`）：
>
> > `GenerateOptions` sampling is `temperature`/`maxTokens`/`stop` only
> > — no `tool_choice`, `top_p`, or penalty fields
>
> 旁邊掛的設計註記叫 `drop-inert-request-knobs`（拿掉沒有作用的旋鈕）。
> 做一個存得起來、卻送不出去的欄位，比沒有這個欄位更糟——你會調它、存它，
> 然後以為它生效了。所以畫面上沒有它。
>
> （`stop` 是支援的，但這一版還沒做。）

## 工具權限那一顆 chip（輸入框上、📎 右邊）

對話框的左下角有一顆盾牌圖示的 chip，寫著這個角色**拿到什麼**（例：`只讀`）。
點開可以當場改，**選了就生效**，不必再按儲存。

它改的是**這一間房**的設定（`room.json` 的 `allowTools`），跟對話頁
「⚙️ 房間」裡那一格是同一個值——只是搬到手邊。選「聽酒館的」＝沿用
⚙️ 設定 那一層（那是預設）。

> ⚠️ 它**不是** DSH 的「訪問模式」。兩件事不一樣，而且會疊加：
> **訪問模式**管的是「工具跑起來之後的沙箱邊界，以及要不要問你」；
> **這一顆**管的是「**這個角色看得到哪些工具**」。
> 所以畫面上只有一個，不會有兩套看起來很像卻效果不同的權限控制。

## 側邊欄的互動（都照原生）

- **區塊標題列整列可點**：點「酒館街」那一列的任何地方就收合／展開（跟下面每一列
  同一個規矩）。只有右邊那顆「＋ 新增酒館」例外。
- **分隔線會跟著你的手**：滑過酒館街與工作區之間那條線時，會出現一段**以游標為中心**
  的光條（照 `widthHandle` 的做法，游標位置寫進 `--dsh-tv-pointer-y`）；拖曳中持續亮著，
  雙擊回復預設比例。
- **包廂列表那一列**：對話在跑的時候，圖示欄換成矩陣跑馬燈（見上）。

## 聊天室的行為

- **貼底**：思考與串流文字進來時自動捲到底；**你自己往上翻紀錄時不會被搶**，
  滑回底部就恢復；送出訊息時無條件貼底。
- 思考（reasoning）顯示成可折疊的「思考」那一列（見下）。

## 「思考」那一列

模型在 reasoning 階段的輸出（`reasoning-delta`）會顯示成一列**可折疊的「思考」**
（燈泡圖示 ＋ 標題 ＋ 收合時的預覽），串流中疊一層流動的高光——形狀照 DSH 原生
的 `ReasoningRow`。放在回覆的**前面**，預設展開，點一下可收合。

思考會寫進 `.jsonl` 的 `msg.extra.reasoning`（SillyTavern 本來就有的自由欄位），
所以帶著走的檔案裡思考不會丟，**也不會混進正文**。

## 安裝

```sh
dsh plugin --profile web add "https://github.com/itdogwowo/dsh-tavern/archive/refs/heads/main.tar.gz"
```

（用壓縮檔網址而不是 `github:owner/repo`：後者需要機器上有 `git`。）

開發時改用 link，改完 client 半會熱重載：

```sh
dsh plugin --profile web add "link:<你 clone 的位置>"
```

裝完**重啟 `dsh web`**。之後只改 `lib/client.js` 通常不用重啟（`dsh-client-hmr` 會推
`rebuilt`）；改到 `lib/` 其他檔案就要重啟。

### 兩條硬規則

1. **零執行期依賴**：每個面都只 import `node:` 與自己的相對檔案。DSH 的 loader 啟動時
   同步導入 loader entry，任何一個插件解析失敗整個 `dsh web` 就起不來
   （[DSH discussion #1884](https://github.com/deepseek-ai/deepseek-harness/discussions/1884)）。
   `verify.mjs` 會強制檢查。
2. **宿主半只依賴 `webServer`**：不碰 `settings`／`agents`／`systemPrompt`。
   多依賴一個核心服務，就多一個「啟動時卡住」的理由。

### 三個面、三種風險

| 面 | 在哪裡跑 | 注入 | 壞掉會怎樣 |
|---|---|---|---|
| 宿主半（`lib/index.js`） | `dsh web` 行程 | **只有 `webServer`** | **整個 DSH 開不起來** |
| 瀏覽器半（`lib/client.js`） | 瀏覽器 | **只有 `slots`** | **整個 GUI 白屏** |
| **Agent 面**（`lib/agent.js`） | **只在 preset 裡** | `systemPrompt` | 只有那個對話開不起來 |

**風險從上到下遞減。能放 Agent 面的東西不要放宿主半。**
可選的依賴一律用 `ctx.inject(deps, cb)`（Cordis 的原生機制），不要寫進 `inject` 陣列。

### 寫入規則（見 [`docs/storage-layout.md`](docs/storage-layout.md)）

- **原子寫入**：所有寫入都是「暫存檔 → rename」，所以斷電時只會是舊的完整版本或新的完整版本，
  不會有寫到一半的檔案。`smoke.mjs` 第 13 項**真的在寫入途中 SIGKILL** 來驗證。
- **不覆蓋**：開新對話、上傳插圖撞名時自動編號；`ensure()` 用獨佔建立。
- **來源圍籬**：DSH 的 `webserver` **本身沒有任何來源檢查**，所以我們自己檢查四件事
  （來源位址、`Host`、`Sec-Fetch-Site`、`Origin`）。真的要用區網／遠端介面時設
  `DSH_TAVERN_ALLOW_REMOTE=1`——放寬的是「只有本機」，「同源」那兩項仍然有效。

### 跨半契約（`smoke.mjs` 第 12、12b 項）

瀏覽器半呼叫的每一個 op，都必須存在於宿主半的路由表。這一條是為了
一個真的發生過的 bug：面板的「＋ 新增角色」呼叫了宿主半沒有的 `character.create`，
按鈕永遠回 `unknown op "character.create"`，而**所有測試都還是綠的**——因為兩半
各自被測，卻沒有人測它們之間的介面。現在這條會把整份原始碼掃一遍來釘住，
**同時涵蓋二進位呼叫**（`sendFile('…')`，也就是圖片上傳與卡片匯入）並容忍跨行寫法。

**12b 是反過來的那一半**：宿主半**不可以**有已經拆掉的舊 op（`chat.*` 那六個），
而客戶端**不可以**還在送它們。第二條才是真正的安全網——「宿主半拆了、客戶端還在送」
的症狀是**按了沒反應**（畫面收到 `unknown op`），不是紅字。

### 怎麼確認裝到的是這一版

看側邊欄酒館街的區塊標題：滑上去的 tooltip 會寫 `dsh-tavern ` ＋ 版本（例如
`dsh-tavern tavern-2.6.48`）。

版本標記有五個，**改版時要一起改**：`package.json` 與 `dsh.plugin.json` 的
`version`、宿主半 `tavern-<版號>`、瀏覽器半 `tavern-client-<版號>`、
Agent 面 `tavern-agent-<版號>`。`verify.mjs` 會逐個比對，少一個就紅。
（`tavern.list` 也會回報宿主半的 `build`——那是**現在真的在跑**的那一版，
所以「改了沒生效」看它最快。）

> 這一節刻意**不寫死版號**：以前寫著 `2.5.1`，改版之後它就變成一句錯的話
> ——而文件說錯話比文件少一段更貴。

### 開不了機時的緊急恢復

```sh
dsh plugin --profile web remove dsh-tavern
```

（移除後如果 `dsh.profile.bundles` 還留著 `dsh-tavern`，也把它拿掉。）

## 為什麼是 v2（而不是修 v1）

v1 的功能面很寬：生成參數覆寫（`agent/request`）、提示詞注入（`systemPrompt`）、
設定持久化（`settings` 命名空間＋自製 schema）、舊資料遷移、顯示層正則引擎。
每一個都要在啟動或每次請求時跟 DSH 核心打交道，彼此糾纏，出事時很難指出是哪一個。

v2 的取捨：**先把「檔案」與「UI」做到不會出事**，其餘功能如果要回來，
應該各自做成獨立插件，而不是塞回這個行程。
