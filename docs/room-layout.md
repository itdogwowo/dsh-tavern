# 房間的儲存佈局（設計）

> 狀態：**規格，尚未實作。** 這一頁是使用者兩條要求的落地設計：
> 「有些設定適合精細化設定而不適合全域設定」＋「房間自己也有資源，所以不能用一個檔案放，
> 應該用文件夾，建立的時候最好直接用 id，也要給我修改位置」。

## 1. 為什麼要改

現在的佈局是：

```
chats/<角色>/<對話名>.jsonl          ← 一個檔案裝一整份對話
art/chats/<角色>/<對話名>/          ← 這間房的插圖（**在別的地方**）
```

三個問題：

1. **房間的資源散在兩棵樹**。「這間房的東西」實際上分成 `chats/` 與 `art/chats/` 兩處，
   而且兩邊都用**對話名**當路徑——改名要同時搬四處（檔名、`.sessions` 對照表、插圖資料夾、
   `tavern.json` 的主圖 key）。舊的 `renameChat` 就是這件事的見證（2.6.6 之後已移除）。
2. **名字當身分**。名字是使用者會改的東西，拿它當路徑等於「改個名字要搬整個世界」。
3. **沒有地方放「這間房自己的設定」**。現在只有 `chat_metadata`（一個自由欄位），
   而使用者要的是**每間房可以有自己的精細設定**。

## 2. 新佈局：一間房＝一個資料夾，身分是 id

```
chats/<角色>/<roomId>/
├── room.json      ← 這間房的設定（人看得懂、可以手改）
├── chat.jsonl     ← 對話本身（SillyTavern 格式，一行一則）
└── art/           ← 這間房的插圖（**跟著房間走**）
    ├── 場景-雨夜.png
    └── 場景-打烊.png
```

- **`<roomId>` 在建立時就固定**，之後永遠不變。改名改的是 `room.json` 裡的 `name`，
  **不動任何路徑**——上面那三個問題一起消失。
- id 的形狀：`建立時間的 base36` ＋ `-` ＋ `隨機 4 碼`（例如 `m1k3x9-a7f2`）。
  可排序、可讀、不需要查表就知道誰先誰後；不用流水號是因為刪掉之後會撞號。
- 使用者看到的仍然是名字（`room.json` 的 `name`，預設是角色名）。
  資料夾名不是給人讀的——**但使用者要改的是 `room.json`，不是資料夾名**。

## 3. 每間房可以有自己的設定（從酒館下放）

「全域適合粗、房間適合細」的分界：

| 設定 | 放哪 | 為什麼 |
|---|---|---|
| 酒館名稱／圖示／店面圖 | 酒館 | 那是「這間店」 |
| `userName`（`{{user}}`） | 酒館 | 「你是誰」跨房間不該變 |
| `userPersona` | 酒館，**房間可覆寫** | 同一個你在不同房間可能有不同身分 |
| `tavernPrompt`（店的規則） | 酒館，**房間可追加** | 店的規則＋這一場的規則 |
| **`roomPrompt`（這一場的指示）** | **房間** | 「這一場是雨夜」「這次她已經知道你是誰」 |
| **`allowTools`（工具權限）** | **房間** | 它本來就是 **per-agent＝per-session** 的（`tools.restrict` 要求 `agent.ctx`），
所以「這一間房只給唯讀、那一間房全開」是**機制上最自然**的粒度 |
| **模型／`reasoningEffort`** | **房間** | session 建立時指定（`create(request)` 吃這兩個），不同房間用不同模型很合理 |
| 開場白（用哪一則） | 房間 | 建立時就決定了，記在 `room.json` |
| 世界書的**內容** | 酒館（`worldbooks/*.json`） | 「這個世界」是店的範疇——**房間一個字都不會改到書** |
| 世界書的**掛載／位置** | 酒館是預設，**房間可覆寫** | 2.6.62 起房間有自己的一層：`worldbookPosition`（這一間房的預設位置）＋ `worldbookOverrides`（逐書的 `enabled`／`position`）。⚠️ **沒列在覆寫裡的書＝照酒館那一層**，所以在圖書館改預設，沒特別調過的房間全部跟著變 |
| 條目的**優先序**（`order`） | 酒館（書的檔案）是預設，**房間可覆寫** | 2.6.71 起 `worldbookEntryOverrides`：`{ "<書 id>": { "<條目的 uid>": { order } } }`。⚠️ 鍵用 `uid` 不是索引（索引會因為書裡插一條而**位移到別的條目**，那是安靜的錯）；⚠️ **書的檔案一個字都不會被改**——書是所有房間共用的 |

## 4. 「我要在哪裡改」

- **對話頁的「📄 檔案」分頁**已經在列路徑——改成列出**這個房間資料夾**的三個東西
  （`room.json` / `chat.jsonl` / `art/`），並且：
  - `room.json` 直接可編輯（面板裡就是表單，存檔寫回同一個檔）
  - 顯示**絕對路徑**＋一顆「複製路徑」（現在只有相對路徑，使用者要自己去接）
- **對話頁多一個「⚙️ 房間」分頁**：上面那張表的「房間」欄位全在這裡。
  分頁順序：💬 對話 / 🖼️ 插圖 / ⚙️ 房間 / 📄 檔案。

## 5. 遷移：**不需要**（使用者同意刪掉重建）

原本這一節寫的是「惰性遷移」，因為舊的 `chats/<角色>/<名>.jsonl` 必須讀得到，
否則使用者的歷史對話會消失。**使用者說「可以刪除重新來」**，所以：

- **不做遷移層**。新的程式只認 `chats/<角色>/<roomId>/` 這一種形狀。
- 舊的 `<名>.jsonl` 留在磁碟上不動（不刪、不搬、不讀）。想留就自己搬走，
  反正它就是一個純文字檔。
- 這樣整個改動少了「兩種形狀並存」的分支——那正是這一類改動最容易長出 bug 的地方
  （每一個讀寫路徑都要記得兩邊都看，漏一個就是「這間房打不開」）。

⚠️ 唯一的代價：改完之後**舊對話在介面上會消失**（檔案還在）。這是刻意的，
而且已經講清楚了。

## 7. 還沒決定

- **id 的格式**：上面提的是「時間 base36 ＋ 隨機 4 碼」。要好念一點可以改 `01`、`02`
  流水號，但刪除後會撞號（要掃資料夾才知道下一個是多少）。
- **舊房要不要顯示「未遷移」標記**：不標的話，使用者分不出「這間房有 `room.json`」與
  「這間房還是舊格式」。
- ~~**`art/chats/<角色>/<名>/` 的既有圖**在遷移時搬進去，還是留在原地用路徑對照？~~
  **已決定（2.6.8）：不搬。** 房間的圖現在走 `chats/<角色>/<房間id>/art/`，舊圖留在
  `art/chats/` 原地（不刪、不搬）——動使用者的圖檔風險比較大。代價是舊圖不會顯示。
  搬進去才符合「房間的資源跟著房間走」，但那是動使用者的圖檔。
